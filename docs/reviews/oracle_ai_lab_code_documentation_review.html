# AGENTS.md

Instructions for AI-assisted work in `oracle-dev-ai-lab`.

## Repository identity

This repository is a controlled Oracle development lab. It contains Docker lifecycle scripts, managed SQL source files, local DB install/test/review workflows, deterministic packaging tooling, and supporting Python unittest checks.

## Mandatory rules

- Work only inside this repository.
- Do not connect to organizational databases.
- When DB access is required, connect only to the local container `oracle-dev-ai-lab-db`.
- Do not execute ad-hoc DDL or DML.
- Represent every database change as a versioned SQL file under `db/src/`, `db/install/`, or `db/rollback/` as appropriate.
- Execute schema changes only through official repository scripts.
- Do not add secrets or real credentials.
- Keep changes narrow and reviewable.
- Update file-level purpose documentation when changing behavior or responsibility.

## File documentation standard

Every source, script, SQL, tooling, test, or generated contract file must begin with a concise stable purpose header that explains:

1. what the file does;
2. where it fits in the lab workflow;
3. whether it changes DB state, validates state, reviews files, or packages output;
4. what it explicitly does not do.

Do not describe the file primarily by historical Goal or Stage numbers. Historical traceability may appear in a changelog or appendix, not in the primary file purpose.

## Standard checks

- `scripts/test.sh quick`
- `scripts/lint.sh`
- `scripts/review-db-code.sh` when DB/review/package files change
- `scripts/package-release.sh` when packaging contracts change

# DEVELOPMENT in Oracle using AI Lab

`oracle-dev-ai-lab` is a repository-local Oracle development lab. It provides a disposable Oracle 26ai Free Docker runtime, managed SQL installation flow, smoke tests, static review checks, and deterministic release-package skeletons for Oracle database development.

The repository is the source of truth. The database runtime is disposable and must be recreated from versioned files in Git when needed.

## What this repository is for

Use this repository as a controlled lab for developing and validating Oracle database objects before adapting the pattern to a broader developer environment.

The current implementation focuses on infrastructure: Docker lifecycle, managed install scripts, DB source layout, smoke object validation, review workflow, packaging workflow, and Python-based repository tooling/tests.

## What this repository is not

This repository is not a production deployment tool, not an organizational database integration, and not a generic Flask application. A small Flask starter app remains only as optional Python tooling/demo infrastructure until a later design decision removes or repurposes it.

## Main operator entry points

- `scripts/lab-up.sh` starts the local Oracle lab DB container.
- `scripts/install-db.sh` runs the managed DB install entry point.
- `scripts/run-db-tests.sh` runs SQL smoke tests against the local lab DB.
- `scripts/review-db-code.sh` runs repository-only review checks.
- `scripts/package-release.sh` creates the deterministic release package skeleton.
- `scripts/test.sh` runs Python unittest checks and, optionally, DB smoke tests.

## Safety model

- No organizational database access.
- No committed secrets.
- No ad-hoc DDL or DML.
- DB changes must exist as versioned SQL files and run through official scripts.
- Runtime state is disposable; Git is authoritative.

## Recommended first read

For code changes, read `AGENTS.md` first. For operating the lab, start with the scripts listed above and `.env.example`.

# Project rules for oracle-dev-ai-lab

## Fixed runtime names

- Repository: `oracle-dev-ai-lab`
- Container: `oracle-dev-ai-lab-db`
- Volume: `oracle-dev-ai-lab-u01`
- Network: `oracle-dev-ai-lab-net`

- Git is the source of truth.
- DB runtime state is disposable.
- All DB changes must be represented as versioned SQL files.

# Contributing

This repository is an Oracle development lab. Contributions should preserve the lab contract: versioned SQL sources, controlled scripts, local-only Docker runtime, deterministic tests, static review, and packaging outputs.

## Contribution principles

- Make one focused change per PR.
- Do not mix historical documentation cleanup with runtime behavior changes unless explicitly requested.
- Do not access organizational databases.
- Do not add secrets or real connection strings.
- Keep Python tooling, shell scripts, SQL files, and tests documented with stable purpose headers.

## Architecture boundaries

Primary repository responsibilities:

- `db/` contains managed Oracle source, install, rollback, test, review, generated, and package artifacts.
- `scripts/` contains repeatable operator commands.
- `tools/` contains deterministic repository-local Python helpers.
- `tests/` contains unittest-based repository and workflow contract tests.
- `src/oracle_ai_lab/` is currently a retained Python starter/demo harness, not the Oracle DB lab runtime.

## Required checks

Run the relevant subset before submitting:

- `scripts/test.sh quick`
- `scripts/lint.sh`
- `scripts/review-db-code.sh`
- `scripts/package-release.sh` when package output changes
