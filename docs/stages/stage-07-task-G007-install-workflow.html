סיכום

Goal 007 הוסיף שלד מבוקר להתקנת בסיס הנתונים המקומי של Oracle AI Lab. נוצר entry point יחיד ב-db/install/install.sql, קובצי SQL מנוהלים ליצירת משתמשי המעבדה ולשמירת מקום להגדרות schema עתידיות, שלד rollback שמרני, script רשמי בשם scripts/install-db.sh, ומסמך docs/install-workflow.md.

המימוש הוא infrastructure-only. לא נוצרו טבלאות עסקיות, לא נוצר LAB_SMOKE_TEST, לא נוספו SQL smoke tests, ולא נוסף מימוש release-management פונקציונלי.

  • db/install/00_create_lab_users.sql
  • db/install/01_create_schema.sql

החלטות שנשמרו

  • Git נשאר מקור האמת לכל שינוי DB.
  • כל שינוי DB עתידי חייב להיות מיוצג בקובץ SQL מנוהל.
  • ה-script מכוון רק ל-container המקומי oracle-dev-ai-lab-db.
  • ברירת המחדל של PDB היא FREEPDB1.
  • לא נשמרו secrets או סיסמאות אמיתיות.
  • לא הוכנסה תלות ב-pytest; בדיקות Python נשארו unittest.

מגבלות בטיחות שנשמרו

  • לא בוצע חיבור לבסיס נתונים ארגוני.
  • לא בוצע חיבור לשום בסיס נתונים.
  • Docker לא הופעל.
  • Oracle DB לא הופעל.
  • לא בוצעו DDL או DML.
  • לא נטענה תאימות runtime של Docker או Oracle.

הנחות חשובות

  • ערכי הסיסמאות יוגדרו רק בקובץ .env מקומי שאינו נשמר ב-Git או בסביבת shell מקומית.
  • runtime validation של CREATE USER, grants ו-schema setup יבוצע רק כשיעד מאוחר יותר יאשר זאת.
  • השלד משתמש ב-SQL*Plus/sqlcl-compatible syntax אך לא הורץ מול Oracle במסגרת Goal 007.

מה לא הורץ ולמה

  • לא הורץ scripts/install-db.sh כי Goal 007 אינו טוען runtime validation.
  • לא הורץ Docker ולא בוצע docker exec, בהתאם לגבולות המשימה.
  • לא הורצו SQL smoke tests, כי הם שייכים ל-Goal 008.
  • לא הורץ utPLSQL, כי הוא שייך לאיטרציות פונקציונליות עתידיות.

מגבלות ידועות

  • קובצי user/schema הם skeleton עם TODOs ולא מימוש runtime מאומת.
  • אין עדיין LAB_SMOKE_TEST.
  • אין עדיין scripts/run-db-tests.sh.
  • אין עדיין review workflow או packaging workflow.
