Stage 15 - שיפור תיעוד מסירה לפני פיתוח פונקציונלי

שלב זה בוצע כמשימת תיעוד ידנית על הענף manual/T015-handoff-documentation-cleanup. מטרתו להקטין בלבול עבור מפתח או AI Agent לפני תחילת הפיתוח הפונקציונלי הראשון.

סיכום

עודכן תיעוד המסירה של הפרויקט כך שהמצב הנוכחי, מבנה התיעוד, גבולות תיקיית docs/stages/, סטטוס Flask starter, וגבולות ה-CI יהיו ברורים יותר.

לא בוצעו שינויי SQL, לא שונה runtime behavior, ולא נוספו אובייקטים פונקציונליים.

קבצים שנוצרו

  • docs/README.md - אינדקס תיעוד חי והיסטורי.
  • docs/stages/README.md - הסבר שתיקיית stages היא תיעוד היסטורי.
  • docs/stages/stage-15-task-T015-handoff-documentation-cleanup.html - דוח שלב זה.

קבצים שעודכנו

  • TODO.md - עודכן כ-ledger נוכחי של מצב הפרויקט והמשימה הבאה.
  • docker-compose.yml - נוספה הערה שמבהירה ששירות app הוא retained Flask starter ולא חלק מ-runtime Oracle lab.

החלטות שתועדו

  • ה-Infrastructure MVP הושלם, והשלב הבא הוא הכנה לפיתוח Oracle DB פונקציונלי ראשון.
  • תיקיית docs/stages/ היא היסטורית ואינה מקור הוראות עבודה פעילות.
  • Flask starter מוגדר כ-retained-but-frozen.
  • CI ירוק אינו מהווה הוכחה ל-Oracle runtime validation; בדיקת DB נשארת באחריות המעבדה המקומית.

הערות יישום

השינוי נועד לשפר handoff למפתח או AI Agent. לכן הוא מתמקד בתיעוד, בניווט, ובצמצום ambiguity בין תיעוד חי לבין תיעוד היסטורי.

פקודות להרצה בסוף לפני PR

  • PATH=.venv/bin:$PATH scripts/test.sh quick
  • PATH=.venv/bin:$PATH scripts/lint.sh
  • scripts/review-db-code.sh
  • git diff --check | cat
  • agw_review_output --run

בדיקות

הבדיקות מיועדות להרצה לאחר commit ו-push, לפני פתיחת PR, בהתאם להחלטת העבודה הידנית במשימה זו.

מגבלות

  • לא הוספו אובייקטים פונקציונליים לבסיס הנתונים.
  • לא שונה תהליך התקנה, בדיקה, סקירה או packaging.
  • לא בוצעה Oracle runtime validation כחלק מהשלב הזה.

השלב הבא

לאחר מיזוג משימת ה-handoff, ניתן להתחיל לתכנן את ה-functional Oracle DB iteration הראשון, תוך הסתמכות על docs/functional-readiness-checklist.md ועל ה-spec הרלוונטי.
